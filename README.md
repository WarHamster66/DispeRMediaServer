# DispeR Media Server

Телеграм-бот для управления домашним медиасервером на Linux: торренты, файловый
менеджер, мониторинг системы и ежедневные отчёты — всё из чата Telegram.

Под капотом: **Transmission** (торренты) · **Samba** (сетевая шара) · **Plex**
(медиатека, опционально) · **Python** + [pyTelegramBotAPI](https://github.com/eternnoir/pyTelegramBotAPI).

## Возможности

- 🔎 **Поиск по RuTracker** — напиши боту «Титаник», и он покажет раздачи с
  качеством (1080p · BDRip · дубляж), размером и числом раздающих — сверху те, что
  скачаются быстрее. Нажал номер — выбрал папку — качается.
- 📺 **Подписки на сериалы** — `/follow Бункер`, и новые серии с LostFilm качаются
  сами в «Сериалы» в 1080p, с уведомлением в Telegram. Бот ходит на сайт сам —
  ничего дополнительно ставить не нужно.
- 🎬 **Торренты** — добавление `.torrent`-файлов и magnet-ссылок прямо в чат,
  выбор папки назначения (со свободным местом на кнопках), **выбор конкретных
  серий** в многофайловом торренте, проверка места перед загрузкой, прогресс в
  реальном времени, пауза/возобновление, история загрузок.
- 📂 **Файловый менеджер** — просмотр, удаление, переименование, перемещение
  файлов и папок через inline-кнопки (с защитой от выхода за пределы шары).
- 📊 **Мониторинг** — CPU, RAM, диски, температура CPU/HDD, аптайм, трафик,
  внутренний/внешний IP, состояние служб, скорость интернета.
- 🌦️ **Ежедневный отчёт** — настраиваемый по содержимому и времени, погода
  через Open-Meteo (бесплатно, без API-ключа — нужен только город).
- 🎞️ **Plex** — после докачки бот автоматически просит Plex пересканировать
  библиотеку, чтобы файл сразу появился (команда `/scan` — вручную).
- 🗄️ **Бэкап** — раз в неделю сохраняет архив `config.json` + `data/` (история,
  настройки) в папку на сервере (`BACKUP_DIR`, по умолчанию `~/media-server-backups`,
  хранит 8 последних). Вручную — команда `/backup`.
- 🕵️ **Аудит** — все опасные действия (удаление, переименование, добавление
  торрентов, обновления) пишутся в отдельный `logs/audit.log` с указанием, кто
  это сделал. Не очищается командой `/clear_logs`. Просмотр — `/audit`.
- 🔐 **Доступ** — команды доступны только пользователям из белого списка.

## Требования

- Ubuntu / Debian (тестировалось на 22.04 / 24.04)
- Python 3.10+
- Права root для установки (systemd, apt, transmission, samba)
- Для поиска по RuTracker — Docker (установщик поставит сам), процессор x86-64 или ARM64

## Установка

```bash
git clone https://github.com/WarHamster66/DispeRMediaServer.git
cd DispeRMediaServer
sudo python3 install.py
```

Установщик в интерактивном режиме:

1. Поставит системные пакеты (transmission-daemon, samba, smartmontools и др.).
2. Опционально установит Plex Media Server и **привяжет его к вашему аккаунту**
   (иначе сервер не увидят телефон и ТВ) — заодно пропишет токен для
   авто-сканирования библиотеки.
3. **Определит все диски, покажет свободное место и предложит, куда складывать
   загрузки** (можно выбрать по номеру или вписать свой путь).
4. Настроит Transmission RPC (включая правило AppArmor), Samba-шару с
   пользователем и паролем, общие права на медиапапку и Python-окружение (venv).
5. Спросит токен бота, Chat ID, ID администраторов, город для погоды, прокси и
   (по желанию) аккаунт LostFilm для подписок на сериалы. Вход на LostFilm
   защищён капчей, поэтому после запуска бот сам пришлёт администратору кнопку
   «Войти на LostFilm» — нажать и ввести код с картинки. Так же — для RuTracker.
6. Предложит включить **поиск по RuTracker** — поставит Docker и FlareSolverr.
7. Создаст и запустит systemd-сервис `media-server` с автозапуском.
8. Предложит закрепить **статический IP** (NetworkManager или netplan).

В конце выведет адрес сетевой папки с логином и паролем.

### Что подготовить заранее

| Что | Где взять |
|-----|-----------|
| Bot Token | [@BotFather](https://t.me/BotFather) |
| Chat ID / User ID | [@userinfobot](https://t.me/userinfobot) |

Погода работает без ключа (Open-Meteo) — нужно только указать город (`WEATHER_CITY` в `config.json`, установщик спросит его сам).

### Нужен ли прокси?

**Нет, если Telegram у вас не заблокирован.** На вопрос установщика про SOCKS5-прокси
просто нажмите Enter — бот будет ходить в Telegram и за погодой напрямую. Это
основной сценарий для большинства стран.

Прокси нужен только там, где доступ к Telegram ограничен (например, Россия): тогда
впишите `socks5h://user:pass@host:port` — через прокси пойдут **только** служебные
запросы (Telegram, погода, поиск по RuTracker). **Торренты качаются напрямую на
полной скорости в любом случае** — Transmission прокси не использует.

Для поиска по RuTracker из России прокси нужен обязательно — сайт заблокирован.

## Конфигурация

- **Секреты** (токены, пароли) — в `.env` (создаётся установщиком, права `600`,
  в git **не** попадает). Шаблон — `.env.example`.
- **Пути и настройки** — в `config.json` (медиапапка, разрешённые/защищённые
  папки, отслеживаемые службы, порог оповещения о месте на диске).

Изменить настройки после установки:

```bash
nano .env            # токены/пароли
nano config.json     # пути и поведение
sudo systemctl restart media-server
```

## Поиск по RuTracker

Пишете боту в личку название — получаете список раздач:

```
1. Титаник / Titanic (1997)
🎞 1080p · BDRip · дубляж
📦 14.2 ГБ · 🟢 523 сидов · ⚡⚡⚡ очень быстро
📅 12.03.2024 · Зарубежное кино (HD Video)
```

Сверху — раздачи, где больше раздающих (сидов): они скачаются быстрее. Нажали
номер — бот скачает `.torrent`, спросит папку и, если в раздаче много серий, какие
из них качать. В группах — командой `/find Титаник`.

**Как это устроено.** RuTracker закрыт проверкой Cloudflare «я не робот», которую
проходит только настоящий браузер. Поэтому рядом с ботом в Docker работает
[FlareSolverr](https://github.com/FlareSolverr/FlareSolverr): бот зовёт его изредка
за «пропуском» (он живёт долго), а ищет и качает обычными быстрыми запросами.
FlareSolverr доступен только с самого сервера (`127.0.0.1:8191`), в простое
занимает ~60 МБ памяти.

**Включить:**

1. Установщик предложит это сам (шаг «Поиск по RuTracker»). На уже работающем
   сервере:
   ```bash
   sudo python3 setup_rutracker.py
   ```
   Скрипт поставит Docker (если его нет) и запустит FlareSolverr с автозапуском.
   Повторный запуск — обновление FlareSolverr.
2. В боте (в личке, администратор): `/rutracker` → логин → пароль (сообщение
   с паролем бот сразу удаляет) → код с картинки, если RuTracker попросит.
3. Из России нужен `PROXY_URL` (сайт заблокирован). Прокси с паролем подходит:
   браузеру FlareSolverr бот сам поднимает локальный мост без пароля.

## Подписки на сериалы (LostFilm)

Бот сам заходит на [LostFilm.tv](https://www.lostfilm.tv) и качает новые серии.
Нужен бесплатный аккаунт на сайте. Проще всего указать его прямо в боте:
администратор пишет боту в личку `/lostfilm`, присылает почту и пароль
(сообщение с паролем бот сразу удаляет) — они сохраняются в `.env` на
сервере. Ещё варианты: установщик спрашивает их сам, или допишите вручную
в `.env` и перезапустите бота:

```bash
LOSTFILM_EMAIL=you@example.com
LOSTFILM_PASSWORD=пароль
```

Вход на сайте защищён капчей: бот пришлёт картинку, ответьте кодом с неё
(`/lostfilm` — в любой момент). Сессия хранится в `data/lostfilm_session.json`
и живёт долго; если она истечёт, бот сам напишет, что нужно войти снова.

| В боте | Что делает |
|---|---|
| `/follow Бункер` | подписка (название по-русски или по-английски) |
| `/series` | список подписок, отписка, «проверить сейчас» |
| `/lostfilm` | указать аккаунт, войти на сайт, проверить вход |

После подписки бот предложит сразу скачать последнюю серию или весь последний
сезон, если он уже вышел целиком.

Настройки в `config.json`: `SERIES_FOLDER` (куда качать), `SERIES_QUALITY`
(`1080`, `720`, `SD`, пусто — любое), `SERIES_CHECK_MINUTES`, `LOSTFILM_URL`
(своё зеркало; по умолчанию бот сам выбирает первое рабочее). Раздачи, закрытые
для РФ, бот повторно запрашивает через `PROXY_URL`, если он задан.

## Перенос медиатеки на новый диск

Купил новый диск (например, 4 ТБ) и хочешь перенести на него фильмы, оставив
загрузки на системном SSD? Подключи диск и запусти:

```bash
sudo python3 migrate_disk.py
```

Скрипт найдёт новый диск, предложит отформатировать (с двойным подтверждением),
смонтирует с записью в fstab, перенесёт выбранные папки и сделает
bind-монтирования — **все пути остаются прежними**, боту/Plex/Samba
перенастройка не нужна. Посмотреть диски из бота — команда `/disks`.

## Решение проблем

### Торренты добавляются, но стоят на паузе (0%)

В Ubuntu демон Transmission ограничен профилем **AppArmor**, который запрещает
запись вне стандартных папок (`/var/lib/transmission-daemon/...`). При загрузке в
`/media`, `/srv` и т.п. в `dmesg` появляется `apparmor="DENIED" ... profile="transmission-daemon"`.
Установщик настраивает это автоматически, но если правка не применилась:

```bash
sudo tee /etc/apparmor.d/local/usr.bin.transmission-daemon > /dev/null <<'EOF'
/media/media-server/ rw,
/media/media-server/** rwk,
EOF
sudo apparmor_parser -r /etc/apparmor.d/usr.bin.transmission-daemon
sudo systemctl restart transmission-daemon
```

(замените `/media/media-server` на свой путь к медиапапке).

### Plex виден на ПК, но не появляется на телефоне и телевизоре

Значит сервер **не привязан к аккаунту Plex** (не «заявлен»). Из локальной сети
Plex пускает в веб-интерфейс без входа в аккаунт — библиотеку добавить можно,
но телефон и ТВ ищут серверы **через аккаунт Plex** и такого сервера не увидят.

Установщик предлагает привязку сам, но если пропустил — привяжи вручную:

1. Открой https://plex.tv/claim, войди в аккаунт Plex и скопируй токен вида
   `claim-xxxxxxxxxxxx` — он живёт **всего 4 минуты**.
2. На сервере:

```bash
curl -X POST "http://localhost:32400/myplex/claim?token=claim-ВСТАВЬ_СЮДА"
sudo systemctl restart plexmediaserver
```

Через минуту сервер появится на всех устройствах с тем же аккаунтом Plex.

Проверить, привязан ли сервер, и заодно достать токен для `PLEX_TOKEN`:

```bash
sudo grep -o 'PlexOnlineToken="[^"]*"' \
  "/var/lib/plexmediaserver/Library/Application Support/Plex Media Server/Preferences.xml"
```

Пусто — не привязан. Есть токен — впиши его в `config.json` (`"PLEX_TOKEN": "..."`)
и перезапусти бота, чтобы работало авто-сканирование библиотеки после докачки.

### Speedtest показывает только скачивание

По умолчанию замер идёт через Cloudflare (без установки), но отдача за DPI/прокси
часто рвётся. Для полного замера (↓ и ↑) поставь официальный Ookla CLI — бот
определит его автоматически:

```bash
curl -s https://packagecloud.io/install/repositories/ookla/speedtest-cli/script.deb.sh | sudo bash
sudo apt install speedtest
```

## Безопасность

- Не коммитьте `.env` — он в `.gitignore`.
- Два уровня доступа (в `.env`):
  - `CREATOR_IDS` — доверенные пользователи: торренты, отчёты, файлы;
  - `ADMIN_IDS` — администраторы: дополнительно `/reboot`, `/update`, `/audit`,
    `/clear_logs`. Если не задано — администратор = `TELEGRAM_CHAT_ID` (владелец).
- Посторонние получают «Нет доступа», а попытки пишутся в аудит-лог (`ACCESS_DENIED`).
- Файловые операции ограничены папкой `SHARED_FOLDER` (защита от path traversal),
  корень шары и точки монтирования дисков удалить нельзя.
- Боту через sudo разрешены только две команды: перезапуск своего сервиса и
  перезагрузка сервера.

### Перезагрузка из бота (для уже установленных серверов)

Новые установки настраивают это сами. На сервере, поставленном раньше, один раз
выполни (замени `disper` на пользователя бота):

```bash
echo "disper ALL=(root) NOPASSWD: /usr/bin/systemctl restart media-server, /usr/bin/systemctl reboot" > /tmp/ms
sudo visudo -cf /tmp/ms && sudo install -m 440 -o root -g root /tmp/ms /etc/sudoers.d/media-server
```

`visudo -cf` проверяет правило до установки — битый файл в `/etc/sudoers.d`
сломал бы `sudo` целиком.
